# 3.2. Kiểm tra điều kiện đánh giá

Theo thiết kế ở mục 2.5, máy chủ kiểm tra quyền đánh giá theo từng chi tiết đơn hàng (`OrderItem`). Tài khoản đang đăng nhập phải trùng với `Order.UserId` và đơn hàng phải đã hoàn thành. Dịch vụ được xác định bằng `OrderItem.ServiceId`, cửa hàng được xác định bằng `Service.ShopId`. Mỗi chi tiết đơn hàng có tối đa một đánh giá.

## Mã đề xuất

Đoạn C# dưới đây minh họa truy vấn EF Core. `db` là `DbContext` của ứng dụng. Tên `DbSet` và giá trị `Completed` cần được đối chiếu với mã nguồn khi tích hợp. Máy chủ lấy `signedInUserId` từ tài khoản đã xác thực.

```csharp
public async Task<bool> CanReviewAsync(
    int orderItemId, int signedInUserId, int serviceId, int shopId)
{
    var eligibleItems =
        from item in db.OrderItems
        join order in db.Orders on item.OrderId equals order.OrderId
        join service in db.Services on item.ServiceId equals service.ServiceId
        where item.OrderItemId == orderItemId
            && order.UserId == signedInUserId
            && order.Status == "Completed"
            && item.ServiceId == serviceId
            && service.ShopId == shopId
            && !db.Reviews.Any(review => review.OrderItemId == item.OrderItemId)
        select item.OrderItemId;

    return await eligibleItems.AnyAsync();
}
```

## Kết quả mong đợi

| Tình huống | Kết quả |
| --- | --- |
| Đúng khách, đúng dịch vụ và cửa hàng, đơn đã hoàn thành, chưa có đánh giá | `true` |
| Dòng đơn không tồn tại hoặc thuộc khách khác | `false` |
| Đơn chưa hoàn thành | `false` |
| Sai dịch vụ hoặc cửa hàng | `false` |
| Dòng đơn đã có đánh giá | `false` |

Nếu hàm trả về `true`, yêu cầu chuyển sang bước kiểm tra nội dung và lưu đánh giá ở mục 3.3. Đoạn mã minh họa chưa được kiểm thử trong ứng dụng.
